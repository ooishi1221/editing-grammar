# Editing Grammar v0.2 Release Readiness Review

## Current state

The current main branch contains 93 Patterns: 82 current-contract, 3
historical-exception, and 8 semantic-only. It also contains six Composition
Frame References, four Composition Sequence References, eight Text Roles,
optional scene-level Composition Handoff, Agent workflow guidance, VS-I15
Product Identity, and Pattern-level retrievalTerms.

This review covers the public integration surface only. It does not revise
the underlying contracts.

## Fresh clone acceptance

The fresh install path succeeds:

~~~
npm ci
npm run build
npm run validate
npm test
~~~

The install completed without vulnerabilities. Build passed, validation
reported 93 Patterns loaded and valid with zero errors, and the test suite
reported 109 passing tests.

The CI workflow matches this path on Ubuntu with Node 24. CI for the reviewed
baseline commit completed successfully.

## Pattern workflow acceptance

The public CLI supports a complete Pattern workflow:

- Search for "数字を大きく" ranks VS-I05 first and visibly reports
  retrievalTerms as the matched positive field.
- Search for "商品同定" and "パックショット" ranks VS-I15 first.
- Search for "話者を識別" returns relevant speaker-treatment candidates.
- Search for "余韻" returns multiple plausible candidates rather than a
  declared winner.
- Compare exposes retrieval evidence separately from decision fields and
  does not choose a winner.
- Show exposes typed parameter declarations, retrievalTerms where present,
  and observed, inferred, and proposal provenance.
- Handoff emits machine-readable JSON, preserves unresolved required inputs,
  and does not select Composition or renderer behavior.

VS-I05 and VS-I15 handoffs with supplied required values have no unresolved
inputs. An unsupplied VS-I15 handoff explicitly leaves productIdentity and
productAsset unresolved.

## Composition workflow acceptance

The production Composition catalog loads and validates through the
source-level API:

- Frames: CF-01 through CF-06
- Sequences: CS-01 through CS-04
- Text Roles: eight catalog entries

The catalog is discoverable in the Composition documentation and Agent Skill,
and a coding Agent can inspect the small catalog directly. There is a
source-level API through loadCompositionCatalog and
buildSceneCompositionHandoff. There is no Composition CLI, which is an
optional convenience rather than a release blocker: Composition is a
scene-level library contract and its catalog is intentionally small.

However, the Skill does not include an executable import and construction
example for the source-level builder. This leaves a fresh coding Agent with
one non-obvious step between the workflow instruction and a concrete call.

## End-to-end scene acceptance

A two-person baseline to guest reaction to baseline return built successfully
with CF-01, CF-02, and CS-01. The supplied contextSubjects and selectedSubject
bindings resolved; restore explicitly referenced the baseline frame
selection; and no geometry or Pattern selection was generated.

A stable creator-frame scene built successfully with CF-02, CF-05, and
CS-04. CS-04 preserves a frame selection while change references a text state
only. HOLD is therefore an affirmative composition state rather than missing
data or a mandatory frame change.

A combined scene handoff built successfully with VS-I15 and CF-06. Supplying
the Pattern productIdentity does not resolve the independently authored CF-06
productIdentity binding. When that binding is omitted, the Pattern handoff is
resolved and the Composition selection remains unresolved, as intended.

A dry-run vertical short was expressible without renderer geometry:

- a shared two-person context used CF-01;
- a selected reaction used CF-02 and CS-01;
- a numeric reveal used VS-I05 and CF-05 where text became primary;
- a continuing line used CS-04 HOLD.

The resulting scene handoff retained explicit targets and state relationships,
without a universal caption template, random composition variation, or
automatic Pattern-to-Composition mapping.

## Agent Skill acceptance

The Skill accurately preserves Search, Compare, Pattern Handoff, historical
handling, and provenance behavior. Its Composition Pass gives operational
guidance for Frame selection, Sequence selection, HOLD, text roles, unresolved
bindings, and the renderer boundary.

The Skill is not fully actionable for a fresh coding Agent because it tells
the Agent to build a SceneCompositionHandoff without showing where to import
the source-level API or a minimal construction call. This is a SHOULD FIX
documentation gap, not a contract defect.

## Validation surface

npm run validate validates only the Pattern catalog. It does not load or
validate composition/frames, composition/sequences, or composition/text-roles.
A malformed production Composition YAML could therefore pass npm run validate
and be caught only by npm test.

This is a SHOULD FIX before release preparation. The validation command should
load the Composition catalog in addition to Patterns and report its validation
result. A CLI-level regression test should ensure this remains true.

## API / compatibility

The reviewed source-level APIs have coherent, explicit responsibilities:

- loadPatterns
- searchPatternsV2
- buildCandidateComparisons
- buildImplementationHandoff
- loadCompositionCatalog
- buildSceneCompositionHandoff
- buildSceneImplementationHandoff

Composition loading has no runtime dependency on the research corpus. Scene
Composition is optional, so existing single-Pattern and v0.1 scene handoffs
remain valid. The reviewed builders copy their inputs and do not expose
renderer geometry, hidden global state, or automatic Pattern/Composition
coupling.

## OSS portability

The public repository path does not require absolute local paths, private
Drive files, BECKY context, a particular Mac, credentials, Remotion, or a
renderer installation. The repository is public. A practical scan found no
tracked secrets, credential files, or bundled third-party screenshots, video,
or audio. Composition research stores URLs and textual observations rather
than copied third-party media.

## Findings

| Classification | Finding |
| --- | --- |
| BLOCKER | None. |
| SHOULD FIX | Extend npm run validate to validate the production Composition catalog and add one CLI regression test. |
| SHOULD FIX | Synchronize the five current public documents, including a minimal source-level Composition builder example in the Skill or linked example. |
| OPTIONAL | Add a Composition CLI in a later phase. The current small catalog and source-level API make this unnecessary for v0.2 release readiness. |

Critical missing regression coverage: one. Add a regression test that proves
the validate CLI loads and rejects invalid production Composition catalog data
after the validation surface is extended. Existing coverage already protects
retrievalTerms, provenance, frozen Search benchmarks and holdout, VS-I15,
Composition loading, research provenance integrity, unresolved bindings,
CS-04 HOLD, optional scene Composition, Pattern/Composition independence, and
backward compatibility.

## Final decision

**GO WITH CHANGES**

The v0.2 contracts are usable end-to-end and have no core release blocker.
One bounded release-surface hardening batch should complete before release
preparation so the public validation command covers every production grammar
catalog and the current documentation accurately describes the available
workflow.

## Exact next batch

1. Extend npm run validate to load and validate the Composition Frame,
   Sequence, and Text Role catalogs, and add a CLI regression test.
2. Synchronize README, CHANGELOG Unreleased, architecture overview, Skill,

Patterns, or release artifacts in that batch.

  loadCompositionCatalog and buildSceneCompositionHandoff.
- Current README, CHANGELOG, architecture, Skill, and Composition contract
  documentation now describe the 93-Pattern v0.2 development surface,
  Composition Grammar, and retrievalTerms.

Release-readiness status after remediation: **GO**.
