# Editing Grammar v0.3 Direction Review

## 1. Real AI-user feedback

The first AI user confirmed that v0.2 is useful to an Agent, but the CLI and
JSON surface alone do not make the resulting visual treatment obvious to a
human producer. Final quality still depends on Agent judgment and renderer
execution.

The feedback identifies two missing loops:

- **Selection:** see what an option can look like, then choose an appropriate
  structural treatment.
- **Verification:** determine whether a rendered result respected the selected
  Pattern and Composition contract.

It also identifies future needs for project-specific Taste and factual
post-publication run records. These are distinct needs and must not be merged
into Pattern truth.

## 2. What v0.2 solved

v0.2 provides 93 Patterns, optional Composition Grammar, deterministic Search
v2, Candidate Comparison, typed Pattern Handoff, optional Scene Composition
Handoff, explicit unresolved inputs, and provenance separation.

It answers:

- What editing jobs exist?
- How can scene attention and relationships be structured?
- How can an Agent hand a selected contract downstream without choosing a
  renderer?

## 3. What v0.2 did not solve

v0.2 does not show a human or Agent what a selected treatment looks like, does
not render, and does not verify a rendered output. It does not choose what
looks good, resolve Taste, detect faces or products, or attribute outcomes to
individual Patterns.

The missing selection loop and verification loop are separate. A visual
example can communicate a possible relationship; an evaluator can verify
whether a selected relationship survived rendering. Neither supplies an
aesthetic verdict.

## 4. Human reference-selection loop

Human reference selection commonly follows:

~~~text
see example
→ identify a useful relationship
→ choose it for this scene
→ adapt it to project context
~~~

A future Reference Example Layer can support that loop if it remains
illustrative. It must not turn one example into a renderer preset, a copy
target, mandatory Taste, evidence of performance, or the one correct
appearance for a Pattern.

Editing Grammar should never choose what looks good. It should provide semantic
options, examples, and constraints. The Agent, project Taste, and scene context
make the aesthetic choice.

## 5. Reference Example Layer

Reference Examples should be an **external** companion layer, not v0.3 core
data yet. Canonical media has ownership, format, and consumption concerns that
are different from reusable editing semantics.

A later minimal definition should be evaluated around only:

- a stable example ID;
- one applicable Pattern, Frame Reference, or Sequence Reference ID;
- media type;
- asset location;
- a concise description of the relationship demonstrated;
- what the media does not demonstrate;
- provenance and redistribution-rights status.

The smallest portable AI-consumption path is **asset plus structured
description**. A multimodal Agent may inspect the asset, but the description
keeps the intended structural relationship available to non-visual consumers.
Machine-readable visual features and embeddings are deferred; no vector
database is justified for an initial catalog.

Canonical example media must use original, synthetic, generated, project-owned,
or explicitly redistributable licensed material. Do not commit third-party
YouTube, TikTok, TV, or CM screenshots or clips. External sources remain
research evidence URLs and timecodes, separate from canonical example media.

The later example spike can cover VS-I05, VS-R02, VS-L03, CF-01, CF-02, CF-05,
and CS-04 only. It must first decide whether each needs a still,
before/after pair, or short clip; it must not migrate all 93 Patterns.

## 6. Evaluator

The first v0.3 implementation should be an **Evaluator companion** with a
strict adapter boundary. It consumes a selected Pattern/Composition contract
plus normalized renderer or timeline metadata, then returns PASS, WARN, FAIL,
or SKIPPED with evidence. It does not rank aesthetics or decide whether the
Agent chose the best edit.

The core library remains responsible for grammar and handoff contracts. A
Video Harness or renderer adapter remains responsible for target identities,
regions, timing, platform profile, and execution metadata. The Evaluator
companion compares those supplied facts with the selected contract.

Initial feasibility:

| Check | Classification | Reason |
| --- | --- | --- |
| E01 required target present | DETERMINISTIC WITH ADAPTER METADATA | Requires emitted target/asset presence records. |
| E02 protected target not occluded beyond threshold | DETERMINISTIC WITH ADAPTER METADATA | Requires target and occluder bounds plus an authored threshold. |
| E03 caption avoids protected target | DETERMINISTIC WITH ADAPTER METADATA | Intersect caption and protected-region bounds. |
| E04 caption reading time / density | DETERMINISTIC WITH ADAPTER METADATA | Requires text, duration, locale, and declared policy. |
| E05 platform safe-area compliance | DETERMINISTIC WITH ADAPTER METADATA | Requires a platform profile and rendered bounds. |
| E06 CF-06 product identity visible and distinguishable | VISION-ASSISTED | Metadata can assert intended placement, not perceptual distinguishability. |
| E07 CS-04 HOLD preserved | DETERMINISTIC WITH ADAPTER METADATA | Requires emitted composition-state or relationship metadata. |
| E08 selected inputs represented downstream | DETERMINISTIC WITH ADAPTER METADATA | Requires explicit handoff-to-render lineage. |

For output-only video with no adapter report, E01 through E05 and E07 become
less reliable or require optional vision. The Evaluator must prefer explicit
metadata rather than claim it can infer faces, products, or quality from a
video by default.

A later minimal result may contain checks with an ID, pass/warn/fail/skipped
status, human-readable message, and evidence, plus unresolved inputs. That
shape belongs in the companion after the first spike proves it useful; it is
not a v0.2 schema change.

## 7. Taste Profile

Taste Profile belongs in **project context**, supplied by an Agent or external
application. It may state preferences such as strong hierarchy, one dominant
idea per beat, restrained effects, or HOLD when meaning is stable.

It must not become universal Pattern truth, a global ranking weight, or a
renderer preset. v0.3 does not need a Taste Profile contract until a real
project context demonstrates a stable, portable use case.

## 8. Outcome / learning loop

Outcome tracking belongs to an **external** analytics store and should come
later, after enough real videos exist. A future factual Run Record may connect
run and video IDs, platform, selected Pattern and Composition IDs, renderer,
publish timestamp, and observed views, likes, comments, saves, or retention.

It must not create effectiveness scores, winner Patterns, best Patterns, or
causal lift claims. A run record is observation, not evidence that a Pattern
caused an outcome.

## 9. Repository ownership boundaries

| Layer | Ownership |
| --- | --- |
| Editing Grammar | Meaning vocabulary, Patterns, Composition, provenance, typed handoff |
| Reference Examples | External companion catalog with licensed or synthetic media and descriptions |
| Creative Video Harness / Renderer | Timeline, assets, geometry, rendering, and normalized execution metadata |
| Evaluator | Companion that verifies selected contracts against adapter metadata |
| Taste Profile | Agent or project context |
| Outcome Store | External post-publication analytics |

This keeps semantic selection, visual illustration, execution, verification,
personal preference, and observational metrics from duplicating each other.

## 10. Evidence / provenance clarification

It is incorrect to say that all Patterns have confidence 0.5. Source-derived
semantic facts can be observed, reusable abstractions can be inferred, and
renderer-neutral implementation guidance is often proposal with 0.5
confidence. These are scoped claims, not one confidence value for an entire
Pattern.

There is currently no evidence that using a particular Pattern improves final
video quality. That would require a separate outcome and study design; it is
not established by catalog provenance.

## 11. Alternatives considered

- **Reference Example Layer first:** directly answers the visual-choice
  feedback, but needs a safe media policy, an ownership model, and a decision
  about stills versus motion before it can be a reliable OSS surface.
- **Reference Example plus Evaluator vertical slice:** attractive as a demo,
  but combines media policy, adapter metadata, and evaluation contracts before
  either boundary is proven.
- **Taste Profile first:** risks turning a local preference into apparent
  library truth without evidence of a reusable project-context contract.
- **Outcome tracking first:** has limited value before enough published runs
  exist and risks accidental causal claims.

## 12. v0.3 priority decision

**P0-B — Evaluator first.**

The real user says the system is most useful when embedded in a larger
production workflow. The current handoff and Composition contracts already
provide explicit obligations, while rendered verification is absent and can be
tested objectively. A bounded evaluator therefore creates direct visible value
without asking Editing Grammar to become an aesthetic recommender.

Reference Examples are the next selection-loop layer after the evaluator
boundary and media policy are proven separately.

## 13. P0 acceptance test

Given one synthetic adapter-metadata fixture whose caption intersects a
protected reaction region, the Evaluator reports a failed E03 with the
intersecting bounds as evidence. The same fixture also evaluates E05 platform
safe-area compliance and E07 HOLD preservation from explicit metadata.

The acceptance criterion is a reproducible contract-violation result, not more
Patterns, schema fields, or subjective beauty scores.

## 14. Exact next implementation spike

Build one evaluator prototype only:

- three deterministic-with-adapter-metadata checks: E03, E05, and E07;
- one synthetic adapter-metadata fixture with an intentionally broken caption
  overlap;
- selected Pattern/Composition handoff as input;
- PASS, WARN, FAIL, or SKIPPED results with concise evidence;
- no raw-video inference, vision model, renderer adapter, new Pattern,
  Composition catalog migration, Taste Profile, outcome store, or Reference
  Example assets.

The prototype should remain a companion boundary experiment until its input
metadata and result contract are proven against a real Video Harness.
